fix(android-test): assert the restored counters, not that an anonId exists

The restore itself worked (the written-back value was byte-identical), but the
follow-up assertion demanded a non-empty anonId. A fresh install that has never
synced legitimately has no anonId yet - getAnonId() only mints one on the first
sync - and the CI emulator is always in that state, so the check could only ever
fail there while passing on a phone that had synced.

The real invariant is that the counters that were snapshotted come back, so the
test now records a baseline before corrupting and compares against it. That is
meaningful on both a fresh emulator and a real device with history.
