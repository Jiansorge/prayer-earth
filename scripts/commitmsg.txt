feat(legal): add a data-deletion request page and the ID button it depends on

Play requires a delete-data URL on the store listing that names the app, gives
the steps prominently, and states what is deleted, what is kept, and any
retention period. Answering "Yes" honestly also needs the request to be
actionable, not just promised - so both halves are here.

- public/delete-data.html, generated by scripts/build-legal.mjs alongside the
  privacy policy and terms, so the three can never drift apart. It is plain
  static HTML rather than an SPA route, so the link keeps working even if the
  app bundle fails to load.
- The process is real, not aspirational: the anonymous ID is the only way to
  identify a record to erase and the user is the only one who holds it, so
  Settings now has a "Copy anonymous ID" button (and a link to the page). A
  full recovery code also works, since it contains the same ID.
- The page states plainly what is deleted (the lifetime record and its
  rate-limiting entry; presence and feed are already swept in ~60s), what is
  KEPT and why (the worldwide prayer total is a shared aggregate that cannot be
  subtracted without lowering it for everyone, and is not attributable; backups
  the user made are theirs; the host may briefly retain an IP address for
  security, separately and with no prayer data), and the retention periods,
  including 30 days for a deletion request.
- It also says that clearing the server record does not erase data already on
  the device, and how to do that - so nobody is misled into thinking their
  phone is clean.

4 new tests assert the button, the link and the ID are all present, since the
published instructions are a dead end if any of them disappears.
