fix(android-test): check the active backdrop canvas, not all six themes

Cycling every theme remounts a live canvas backdrop six times, which destroyed
the execution context on the WebView emulator and failed the job with "Promise
was collected". The real phone risk is not "does theme 4 work" but "is there a
sized canvas at all, since a missing one is a black screen". So assert the
active theme renders a canvas with non-zero dimensions, and leave the full
six-theme matrix to the web suite where it runs reliably.

compare-test-coverage.mjs still lists backdrop/theme as web-only, which is now
accurate rather than a gap: full matrix on web, black-screen smoke on device.
